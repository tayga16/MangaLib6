# OldLib 0.1.0 для Android 2.3 — тестовая версия

Нативный Java-интерфейс в цветах iOS-версии. Минимум Android 2.3 (API 9),
целевая версия Android 2.3.3 (API 10). OldLib развивается в одном репозитории
с MangaLib6 для iPhone/iPad; у платформ отдельные версии и релизы.
Версия 0.1.0, внутренний номер сборки 16. Это продолжение Android-сборок
MangaLib6 0.1.x-test: пакет и ключ подписи сохранены, APK обновляет приложение
с сохранением истории, места чтения и скачанных глав.

Скачать: [OldLib 0.1.0](https://github.com/tayga16/MangaLib6/releases/tag/oldlib-v0.1.0).

Есть поиск через интернет, карточка манги, открытые переводы глав,
постраничное чтение, свайпы, увеличение, следующая глава, история поиска
и сохранение страницы для каждой манги. Запросы идут прямо на MangaLib.
На главном экране истории есть «Проверить соединение».

Для HTTPS встроен Bouncy Castle TLS 1.2 с SNI. Проверяются имя сервера,
цепочка сертификатов и сроки действия; корневые сертификаты включены
в APK из Mozilla CA bundle. На телефоне должна быть правильная дата.
В 0.1.12-test ключи всех корневых сертификатов больше не декодируются
при запуске: на HTC Explorer это задерживало инициализацию и поиск
до истечения тайм-аута. PKIX читает ключ подходящего корневого сертификата
при проверке цепочки; проверка подписей, имени сервера и сроков сохранена.
В журнал записывается время подготовки HTTPS.
В 0.1.11-test из TLS-предложения исключён ChaCha20/Poly1305: при диагностике
HTC Explorer его обработка занимала рабочий поток до истечения тайм-аута.
Используются поддерживаемые AES-наборы TLS 1.2 с прежней проверкой сертификатов.
Время загрузки на HTC после этого изменения ещё нужно проверить.
Обработчики ключей RSA/EC/DSA и проверка подписей регистрируются явно: R8
сохраняет необходимые классы после уменьшения APK. Это исправляет ошибку
«Algorithm identifier of public key of trust anchor could not be read».
При таймауте, обрыве и HTTP 502/503/504 выполняется один повтор.
HTTP 403/429 отображаются без автоматического повтора.
Запросы API начинают с `api.cdnlibs.org`. При HTTP 502/503/504, сетевом
обрыве или ошибке DNS приложение пробует `api.lib.social` и запоминает
успешный адрес. На запрос выполняется не более двух попыток; ошибка
показывает имя сервера и обе причины, если недоступны оба адреса.
HTTP 403/429 и ошибки сертификатов не запускают переключение API.

В 0.1.7-test HTTPS-соединения повторно используются для запросов на один
сервер и порт: следующие страницы обходятся без нового DNS-запроса,
TCP-подключения и проверки сертификата. Для API и картинок сохраняются
отдельные соединения; свободных соединений не больше четырёх, время простоя
не больше 30 секунд, общее время жизни — не больше двух минут. При обрыве
сохранённого соединения выполняется одно переподключение в пределах текущего
тайм-аута. Неполные ответы и соединения с `Connection: close` не сохраняются.
При сворачивании свободные соединения закрываются, при выходе — все.
Сначала запрашивается поддерживаемый исходник страницы с серверов
`download`, `main` или `secondary`. Сжатая копия `compress` используется
при недоступности исходников; следующая страница снова пробует исходник.
Рабочий сервер исходников запоминается. На сервер картинки даётся одна попытка до 12 секунд,
затем пробуется следующий адрес в пределах общего времени загрузки.
Предзагрузка использует те же соединения.

Весь поиск или загрузка ограничены 30 секундами, включая очередь, DNS,
HTTPS и повторные попытки. Каждая попытка API занимает не более 12 секунд.
При истечении общего времени резервный API больше не запрашивается.
При новом поиске и переходе назад старый запрос отменяется, его сокеты
закрываются. Отдельный таймер интерфейса снимает состояние загрузки
и показывает кнопку повтора, даже если рабочий поток ещё не вернулся.
В 0.1.5-test закрытие сокетов перенесено в фоновый поток: отмена и таймер
интерфейса не ждут `Socket.close()`, который может задерживаться в старом эмуляторе.
Над поиском показывается счётчик до 30 секунд и кнопка отмены. Ошибка появляется
также в отдельном окне и карточке на экране поиска. При возвращении в приложение
проверяется истёкшее время с учётом сна устройства.
Медленная передача по одному байту также ограничена общим временем.

На Android 2.3 поддерживаются JPEG, PNG и GIF. При неподдерживаемом
формате страницы приложение пробует следующий сервер изображений.
Читалка открывается на полный экран: системная строка и панели скрыты,
касание страницы показывает или скрывает панели. Двойное касание увеличивает
страницу, свайп перелистывает. Кнопка «Назад» сначала возвращает панели.
Внизу остаётся компактная полупрозрачная строка с номером страницы,
остатком главы и счётчиками «Буфер» / «Назад», как в iPad-версии.

В 0.1.10-test разрешение страницы больше не ограничено размером экрана:
уменьшение применяется только по доступному объёму памяти. На Android 2.3.3+
при увеличении видимый участок повторно декодируется из исходника в фоне.
В 0.1.11-test декодер переиспользуется до смены страницы. Размер участка
подбирается под текущий масштаб и лимит памяти, без лишних исходных пикселей.
Запас по краям в 15% экрана позволяет сохранять чёткий участок при небольшом
перемещении. Повторное декодирование не запускается, если участок уже содержит
видимую область с подходящим разрешением. Задержка после движения — 40 мс,
при активном увеличении двумя пальцами — 100 мс; после отпускания — 40 мс.
Если участок закрывает видимую часть страницы, полное изображение под ним
не рисуется второй раз. Масштаб и положение страницы сохраняются.
Отдельный участок занимает не больше одной восьмой памяти Java (до 4 МиБ).
На Android 2.3/2.3.2 остаётся улучшенная полная страница без декодирования участка.
Исходные файлы временно хранятся в дисковом кэше на 64 МиБ; текущая страница
защищена от вытеснения. GIF и ошибки кэша сохраняют обычное изображение.
Ранее скачанные сжатые главы нужно удалить и скачать снова для получения исходников.

В 0.1.13-test JPEG сразу декодируется с более высоким разрешением в RGB565:
при расчёте лимита учитываются два байта на пиксель. Для PNG/GIF остаётся
резерв в четыре байта; при нехватке памяти размер изображения уменьшается.
JPEG 1970×2800 на HTC Explorer теперь отображается из изображения 985×1400
вместо 492×700, поэтому обычный зум 2,5× использует уже готовые пиксели.
На Android 2.3.3+ центральный участок для зума 4× готовится в фоне через
150 мс после показа страницы и сохраняется при уменьшении. Увеличение во время
подготовки не теряет этот участок. Для сильного увеличения в другой части
страницы и очень больших исходников может понадобиться фоновое декодирование.
Повторное открытие страницы использует исходный файл из дискового кэша
без скачивания; при повреждении или отсутствии файла остаётся загрузка по сети.

Буфер содержит текущую и до четырёх следующих страниц, а также до двух
предыдущих. Предзагрузка выполняется по одной и отменяется при перелистывании,
смене главы или сворачивании приложения. Декодированные изображения занимают
не больше четверти доступной памяти Java (максимум 8 МиБ).
В 0.1.14-test заполнение памяти чёткими страницами больше не останавливает
предзагрузку: следующие исходники скачиваются в дисковый кэш без декодирования.
При перелистывании они декодируются локально без сетевого запроса.
Счётчики «Буфер» / «Назад» включают готовые исходники и проверяют их наличие;
при вытеснении файла из кэша страница снова доступна для предзагрузки.
При предупреждении о памяти остаётся текущий bitmap, сохранённые исходники
и их предзагрузка сохраняются. Чёткость отображаемой страницы не уменьшается.
В списке глав и «Загрузках» показывается дата публикации в формате ДД.ММ.ГГГГ.
Используется `created_at` первого перевода в `branches`, с резервом на дату главы.
Если API не передал корректную дату, показывается «Дата публикации не указана».
При скачивании metadata главы уже сохраняется целиком, поэтому дата доступна
и без интернета; дата не смещается при смене часового пояса телефона.
В списке глав кнопка «Скачать главу» сохраняет все страницы во внутреннюю
память приложения. Отдельная кнопка есть и в читалке: коснись страницы,
чтобы показать её в полноэкранном режиме. Прогресс и отмена видны над списком. На главном экране
«Загрузки» позволяют читать без интернета, продолжить незавершённую загрузку
или удалить её. Отмена, сворачивание и новый запрос приостанавливают скачивание;
сохранённые страницы не загружаются повторно. Каждая страница ограничена
30 секундами, при таймауте загрузку можно продолжить вручную.
Главу можно читать после полного сохранения; следующая скачанная глава
открывается без API. «Продолжить читать» также использует локальные страницы.
Удаление загрузки сохраняет место чтения. Удаление приложения удаляет главы.

## Сборка

Нужны Python 3, JDK 17, Android SDK Build Tools 34.0.0 и платформа android-34
для упаковки ресурсов. Java-код компилируется с API Android 2.3.3;
R8 собирает один DEX с min-api 9. AndroidX, Google Play Services и NDK не нужны.

```powershell
$env:JAVA_HOME = 'путь к JDK 17'
$env:ANDROID_SDK_ROOT = 'путь к Android SDK'
python android/tools/fetch_dependencies.py
python android/tools/build.py
```

Результат: `android/build/OldLib_0.1.0_Android_2.3.apk`.
Тестовый ключ хранится локально в `android/.signing/`, в Git не добавляется.
APK имеет подпись v1 для старого Android; сборка проверяет подпись с API 9.
Следующий APK, собранный тем же ключом, устанавливается поверх предыдущего.

## Проверка

`python android/tools/check_quality.py` проверяет сохранение разрешения,
ограничения памяти для длинных и огромных страниц, подбор разрешения при зуме,
сохранность исходных байтов, защиту текущего исходника от вытеснения
и освобождение дискового кэша. Проверяются повторное использование декодера,
отмена до открытия и освобождение после завершения активного декодирования.

`python android/tools/check_downloads.py` проверяет сохранение частичной главы,
восстановление после создания нового хранилища, продолжение, проверку SHA-256,
исправление повреждённой страницы, смену состава главы и безопасное удаление.

`python android/tools/check_buffer.py` проверяет границы предзагрузки,
возврат к предыдущим страницам, освобождение памяти и сброс при смене главы.
Проверяется регрессия HTC с JPEG 2 758 000 байт и буфером 5 МиБ: предзагрузка
четырёх исходников продолжается при заполненной памяти, исходники учитываются
без повторной загрузки, удаление файла возвращает страницу в очередь,
переход вперёд освобождает bitmap и сохраняет оригинал для возврата.

`python android/tools/check_deadlines.py` моделирует зависший `Socket.close()`
и проверяет, что отмена возвращается сразу, а следующий запрос имеет свой предел времени.

`python android/tools/check_tls.py --optimized` проверяет TLS-клиент после R8
на локальном TLS 1.2 сервере: загрузку хранилища без декодирования ненужных
ключей, доверенную RSA-цепочку среди нескольких корневых сертификатов,
выбор AES при предпочтении ChaCha на сервере,
отказ при неверном имени и недоверенной цепочке, SNI,
gzip, chunked HTTP, перенаправление, повтор 502 и отсутствие повторов 403.
Проверяются переход на резервный API при 502, сохранение успешного адреса,
ограниченное число попыток и остановка при 403.
Проверяются повторное использование одного TCP/TLS-соединения для gzip,
chunked с завершающими заголовками, перенаправления и ответа 204;
разделение соединений по портам, переподключение после молчаливого обрыва,
закрытие по `Connection: close`, отклонение неполных и неоднозначных ответов,
закрытие свободных соединений и запоминание рабочего сервера картинки.
Проверяются предпочтение исходника перед валидной сжатой копией,
резервная сжатая копия при неподдерживаемом ответе и возврат к исходникам.
Проверяются зависший ответ, медленные заголовки и тело, общий предел
времени поиска и освобождение очереди после отмены старого запроса.
`python android/tools/check_tls.py --reuse-optimized --ec` проверяет EC-цепочку
в той же уменьшенной сборке; `--reuse-optimized --expired` — просроченный
сертификат. Повторное использование требует сначала собрать тест с `--optimized`.
Тест R8 в формате classfile выполняет удаление и переименование классов;
оптимизации инструкций отключены из-за ошибки R8 8.2 в этом режиме.
Сборка APK выполняет обычные оптимизации R8 для DEX с min-api 9.
Для генерации временных сертификатов нужен Python-пакет `cryptography`.

`python android/tools/check_transport.py` проверяет живой поиск MangaLib,
информацию, главы и загрузку страницы. При подготовке 0.1.4-test живые
запросы возвращали HTTP 502 как Java-клиенту, так и обычному Python-клиенту.
Ответ DDoS-Guard «шлюз сайта не получил ответ сервера» означает, что шлюз
не получил ответ от сервера сайта. Ограничение времени исправляет зависание
приложения; оно не устраняет недоступность API на стороне сайта.
`python android/tools/check_device.py` собирает отдельный диагностический DEX
с оптимизациями APK для запуска через `app_process` на Android 2.3.
Он измеряет подготовку HTTPS, три поиска, карточку, главы и первую страницу
без отладчика и без изменения данных приложения.
На подключённом HTC Explorer с Android 2.3.5 подготовка HTTPS заняла
1,7 секунды; три поиска — 11,8 / 1,1 / 0,3 секунды; загрузка первой
страницы — 5,4 секунды. Запросы карточки и глав также прошли.
Это отдельная проверка транспорта на телефоне.

`python android/tools/check_zoom_device.py` собирает временную инструментальную
проверку исходников читалки с R8 в отдельном пакете. Она запускается в процессе
целевого приложения на HTC с лимитом памяти 20 МиБ. Отражаемые имена сохраняются
только в тестовом DEX; проверка не заменяет проверку оптимизированного APK в UI.
Для запуска нужен JPEG 1970×2800 по пути
`/data/local/tmp/mangalib-page-check.image` и установленное основное приложение:

```powershell
adb install -r android/build/zoom-device-check/zoom-check.apk
adb shell am instrument -w ru.mangapad.legacy.zoomcheck/ru.mangapad.legacy.zoomcheck.ZoomDeviceCheck
```

На HTC Explorer JPEG занял 2 758 000 байт и декодировался за 585 мс.
Участок 642×962 с исходным разрешением занял 1 235 208 байт, подготовка —
661 мс; три последовательных изменения масштаба — 6 мс без повторного
декодирования, рисование увеличенной страницы — 49 мс. Это измерения одной
страницы; время зависит от исходника, движения и нагрузки устройства.

## Зависимости

- Bouncy Castle `bcprov`, `bcutil`, `bctls` jdk15to18 1.83:
  https://www.bouncycastle.org/licence.html (MIT).
- Mozilla CA bundle из https://curl.se/ca/cacert.pem; лицензия и источник
  приведены в заголовке файла.
- Android 2.3.3 API stubs и JSON 20080701 нужны только для сборки,
  JSON во время работы предоставляет Android.

Скачанные зависимости находятся в `android/deps/`; их SHA-256 записаны
в `android/dependencies.sha256`. Зависимости не загружаются при запуске приложения.
